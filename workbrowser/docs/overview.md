# Workbrowserの概要・基本仕様

最終更新: 2026-11-17。

## 1. アプリの目的

Chromeのサイドパネルから自然言語で質問・指示し、情報の取得・整理と、依頼したブラウザ操作を行うための拡張機能。業務・私用という区別で操作を制限せず、ユーザーの依頼とアプリの権限設定に従う。定型文の一致だけで処理を選ぶのではなく、AIが観察結果に応じて次の操作を選ぶReActループを持つ。

主な用途:

- 現在ページの要約、重要な点の整理。
- 名前・日付・金額・所在地などの抽出と表への整理。
- 指定URLへの移動、関連リンクや検索結果をたどる調査。
- 複数ページやページ送りを使った情報収集と比較。
- 取得内容、参照元URL、取得できなかった範囲を含む回答。
- 指示された入力・選択・編集・削除・送信。検出した送信・保存・削除は承認設定に従う。

AI agentモードでは英語・日本語・フランス語など、設定したモデルが対応する言語で依頼できる。回答も原則として指示の言語に合わせる。UIは英語に統一し、言語切替は設けない。

## 3. 構成と役割

開発時:

```text
会社PCのChrome
  └─ Workbrowser拡張（UI・ReActループ・ブラウザ操作・履歴）
       └─ HTTP / JSON → ローカル開発サーバー（認証・設定・モデル通信）
                         └─ Google Cloud認証 → Vertex AI上のGemini
```

Workstationsで開発する場合は、開発サーバーをWorkstations上で動かし、Chromeが動く会社PCのlocalhostまでポートを転送する。ブラウザ操作は会社PCの拡張内で行う。サーバーが別のブラウザを起動する構成ではない。

| 部分 | 担当 |
| --- | --- |
| Chrome拡張 | 指示の受付、対象タブ、観察と操作、ループの進行、停止、端末への保存 |
| 開発サーバー | 拡張の認証、管理設定、モデルへ渡すコンテキストの検証、Google認証、Gemini REST通信 |
| AIモデル | 取得情報を読み、次のツールと引数を選択し、回答を生成 |
| ブラウザ操作層 | Chrome debugger / CDPによる観察・入力。Puppeteerはフレーム管理に利用 |

操作層はNanobrowserから再利用したもの。エージェントのループ・ツール公開・プロンプト・反復抑止もNanobrowserの構成を参考にしている。[第三者ライセンス](../THIRD_PARTY_NOTICES.md) を参照。

## 4. 起動後のUIと利用手順

拡張をChromeへインストールし、必要に応じてツールバーへピン留めする。アイコンをクリックするとサイドパネルを開く設定になっている。表示するUIは閲覧中のページのサイト許可とは独立している。

初期画面の主なパーツ:

| パーツ | 用途 |
| --- | --- |
| Workbrowserヘッダー、＋、Chat / History、Settings（⚙） | アプリ名、新しい会話、会話画面・端末内の履歴の切替、設定への入口を1行に表示 |
| サンプル指示 | 押すと指示入力欄に例を設定 |
| 対象タブのタイトル | 今回の作業対象を表示 |
| 指示入力欄、Run | 最初は1行で、入力に合わせて高さが広がる。上限に達した後は入力欄内をスクロール |

実行モード（AI agent / Offline demo）はSettings → Connection & AI → Execution modeで選ぶ。選択は端末内に保存し、次のタスクから適用する。AIのプロバイダー・モデル名も同じ設定画面のAI connectionで確認できる。

同じ会話で送った過去の指示・回答・作業メモ・操作結果を次の依頼にも渡す。「前回のどこで間違えた？」などの質問にも使える。＋で新しい会話を作り、Historyから保存済みの会話を開き直せる。保存範囲はChromeプロファイル全体で最新20タスク。操作詳細は実行ごとに24,000文字までで、省略箇所には印を付ける。画像そのものは履歴に保存しない。

Settings → Sites & permissions → Action permissionsで、操作の確認方法を設定する。

| 設定 | 動作 |
| --- | --- |
| 既定のAsk | 検出した送信・保存・削除の前に確認する（初期値） |
| 既定のAuto | 指示された操作を追加確認なしで実行する |
| サイト別Allow | 既定がAskでも、そのサイトで指示された操作を許可する |
| サイト別Ask | 既定がAutoでも、そのサイトでは都度確認する |
| サイト別Block | そのサイトの検出した送信・保存・削除を禁止する |

サイト別ルールはHTTP(S)のオリジン（プロトコル・ホスト・ポート）単位で、既定設定より優先する。閲覧許可・AI送信許可とは独立しており、操作をAllowにしても未承認サイトへアクセスできるようにはならない。設定変更は管理者のみ可能。

確認が必要な場合、入力欄の位置に対象・サイト・操作内容を示す承認カードを表示する。Approve onceで今回だけ承認、Declineで拒否する。管理者はAlways allow on this siteでサイトのAllowを保存できるが、サイトに明示的なAskルールがある場合はこの選択肢を表示しない。承認時に最新の設定と対象を再確認する。Stop、確認期限切れ（2分）、拡張再起動では承認待ちを取り消し、古い返信を受け付けない。

DOMの情報だけでは対象が分からない場合、画像対応Geminiにスクリーンショットを送る。Nanobrowser由来の赤い枠と要素番号（a12など）を画像に重ね、AIが番号を指定して操作する。対象不一致・候補の曖昧さなど、入力がまだ届いていない一部のエラーでは自動で画像へ切り替え、AIからの画像要求にも対応する。対応する番号のない領域やCanvas内の任意座標操作は対象外。未知の送信結果や制限された操作を画像で迂回することはない。

実行中は進捗・操作履歴・Stopを表示し、終了後は回答・参照元・作業メモ・取得テキストの保存ボタンを表示する。回答は文字として表示し、Markdownを専用レンダラーで描画する機能はない。実際に観察した参照元は別のリンク一覧にも表示する。

Activityを開くと、実際に開いたURL、クリックしたボタン・リンク名、入力欄やドロップダウンと確認できた値、失敗理由を時系列で表示する。対象名と値はブラウザ操作層の結果を使い、入力値を引数からそのまま表示することはしない。失敗・送信結果不明・変更不要も区別する。「次の操作を選択中」などの進行状況は上の状態表示に使い、同じ文言をActivityへ繰り返し追加しない。詳しい元データはActivity内のRaw operation logで確認できる。旧形式の履歴は保存済みの内容を表示し、当時記録されていない詳細は復元しない。

現状はログインボタンがなく、SettingsでServer URLとLocal connection tokenを入力して `Connect & save` を押す。これは開発用の接続設定であり、Googleアカウントへのログインではない。

利用例:

```text
Summarize this page and highlight the key risks.
Extract company names and addresses from this page as a table.
Go to https://example.com and compare the pricing plans. Include source URLs.
このページから日付と金額を抽出して。
関連ページも確認して、違いを日本語で説明して。
Résume cette page en français et cite les sources.
```

Runのほか、Ctrl+Enter / Command+Enterでも開始できる。URLがなければ現在ページから始め、URLが指定されていればAIが移動を選ぶ。現在ページが未承認でも、そのページを観察せずに承認済みURLへ明示的に移動できる経路がある。

## 5. ReActループ

1. 拡張が利用者・設定・モデル接続状態を確認する。
2. 新しい会話では読取可能な現在ページを観察する。継続会話ではモデルが必要に応じて観察を選ぶ。
3. 指示、観察、作業メモ、これまでのツール結果を開発サーバーへ送る。
4. サーバーがサイトの送信許可を検証し、ツール定義とともにAIへ送る。
5. AIがJSONの関数呼び出しとしてツールと引数を返す。
6. 拡張が引数と最新の設定を確認し、ツールを実行する。
7. 操作結果を次のAI呼び出しへ返す。完了、一部結果、停止、失敗、上限などで終了する。

モデルに公開するツールは `snapshot`、`read`、`find`、`screenshot`、`navigate`、`click`、`set`、`fill_form`、`type`、`press`、`hover`、`scroll`、`wait`、`remember`、`done`。承認への回答や権限設定の変更はモデルのツールとして公開しない。

固定システムプロンプトは、履歴に追加せず、Geminiへの各APIリクエストの`systemInstruction`に1回だけ含める。現在の`generateContent`方式では前回のリクエストをAPI側が保持しないため、初回だけ送って以降省くことはできない。通常の質問や過去の作業の振り返りは、ブラウザ操作を完了した証拠を必須とせず回答できる。

1回のモデル応答から実行するのは最初の1ツール。追加で返された呼び出しには未実行の結果を返す。古い要素参照など、入力送信前のエラーはAIが再観察して修正できる。入力が届いたか不明な操作は自動再実行しない。

作業メモを保持して長い調査に対応する。メモがある状態でコンテキストが大きくなった場合、古い観察結果を縮小する。すべての情報を無制限に保持する仕組みではなく、上限や欠落は一部結果として扱う。

## 6. モードの違い

| 項目 | AI agent | Offline demo |
| --- | --- | --- |
| 外部AI | 設定済みモデルへ通信 | 呼び出さない |
| 指示の扱い | モデルが解釈し、観察結果で次の操作を選ぶ | 決まった形式から固定の手順を作る |
| 開発サーバー | 必要 | 必要 |
| ブラウザ操作 | 実際のChromeを操作 | 実際のChromeを操作 |
| 主な用途 | 調査・抽出・要約 | UIと入力・クリック等の確認 |

Offline demoは見た目だけのサンプルではない。付属のデモCRMでは100件の更新処理も行う。AI agentはユーザーが依頼した調査・操作を実行し、検出した送信・保存・削除は権限設定と承認に従う。AI未設定時に自動でOffline demoへ切り替えることはない。

## 7. データ、認証、サイト制限

- AI agentでは指示、許可されたページ本文・要素名・URL、操作結果、作業メモをサーバー経由でモデルへ送る。URLにはクエリが含まれることがある。
- 承認済みサイトのマスク済み・枠と番号付きスクリーンショットを、必要時にモデルへ送る。任意スクリプト、アップロード、任意の既存タブ選択、座標操作は公開しない。
- ページの内容は非信頼データとして扱う。ページ内の指示で権限や設定を変更しない。
- 操作許可 `allowedOrigins` とAI送信許可 `modelOrigins` の両方にあるオリジンを使う。サブドメイン、プロトコル、ポートは個別指定。
- `modelOrigins` は初期値が空。期限付きの操作制限解除でもAI送信許可は広げない。
- iframeにも送信・操作許可を適用する。過去に観察した参照元も、次のモデル呼び出しの前に再評価する。
- ページの既知の秘密入力欄は操作層でマスクする。ただし一般的な個人情報や企業秘密をすべて分類する仕組みではない。
- `.data/dev-token` は拡張から開発APIへ接続するための認証キー。Gemini用認証でも社員の本人確認でもない。
- ローカル開発では、サーバー側でgcloudのADCを利用する。本番はCloud Runの実行用サービスアカウントを使う計画。
- 指示、回答、メモ、参照元、取得テキスト、操作履歴は `chrome.storage.local` に保存する。サーバーは会話履歴をストアへ永続化しないが、モデル問い合わせ時には処理する。

## 8. 主な上限と制約

| 項目 | 現在の仕様 |
| --- | --- |
| 実行対象 | 一度に1タスク、開始時に選択したタブ |
| UIからの指示入力 | 最大8,000文字 |
| AIターン数 / デモステップ数 | 初期250。管理画面では1〜500 |
| 実行時間 | 初期30分。管理画面では1〜60分 |
| 履歴 | Chromeプロファイル内で最大20実行 |
| 取得テキストのローカル保存 | 1実行あたり最大200,000文字 |
| 操作履歴 | 実行内で最大500件またはUTF-8で96,000バイト。古い記録を省略した場合は表示する |
| 元の操作ログ | 実行内で最大24,000文字 |
| 一時的な操作制限解除 | 管理者が利用者ごとに最大24時間 |

Stopは後続操作を抑止する。送信済み操作は取り消さない。拡張再起動後は実行中のタスクを中断扱いとし、自動再開しない。同じ会話の新しい指示には保存済みの過去のやり取りを渡すが、過去の要素番号は再利用せず現在ページを観察する。

ログイン、CAPTCHA、秘密情報の入力、決済、アクセス権の付与は手動対応が必要。送信・削除の判定はボタン名とフォーム構造に基づくため、入力時の自動保存などすべての変更を検出できるわけではない。対象タブでの手動操作の自動検知、複数タブの本格的な制御、PDF・Office・画像の専用解析は未実装。
