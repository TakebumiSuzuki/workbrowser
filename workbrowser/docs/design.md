# 設計と決定事項

利用者向けの画面・機能・上限を含む基本仕様は [overview.md](overview.md)、移行先での作業は [workstations-setup.md](workstations-setup.md)、本番対応の追加実装は [cloud-migration.md](cloud-migration.md) を参照する。この資料は技術的な決定事項を記録する。

## 目的と操作

会社の社員向けの汎用ブラウザエージェント。英語を主な利用言語とし、日本語を含むモデル対応言語で指示と回答ができる。現在ページの情報抽出・要約、URL指定による移動、関連ページの調査と結果の整理に対応する。

## エージェント

Nanobrowserの `src/agent/loop.ts`、`tools.ts`、`prompt.ts`、`guards.ts` を参考に、Workbrowser固有のサーバー構成に合わせた1つのループを実装する。

- 拡張がブラウザ操作と実行状態を所有し、サーバーがモデル認証とモデル呼び出しを所有する。
- モデルへツール定義と観察結果を送り、関数呼び出しを受け、結果を次の呼び出しへ返す。
- 観察・読取・検索・クリック・入力・移動・スクロール・待機、作業メモ、最終回答をモデルが選ぶ。
- 1モデル応答につき最初の1ツールだけを実行。追加の呼び出しには未実行の結果を返し、古い要素の連続操作を避ける。
- 要素参照は操作層が管理。事前エラーはモデルが再観察して修正できる。送信済みか不明な操作は再実行しない。
- 作業メモを維持し、必要に応じて古い観察結果を縮小。上限を超える場合は一部結果として終了する。
- 指示文全体・最近の観察・作業メモ・モデルのopaque thought signatureを維持する。
- 反復・無効果・連続失敗・ターン数・時間を制限する。終了時は回答と実際の参照元一覧を表示する。

## AI接続

Vertex AIのGemini RESTを主な会社向け経路とする。モデルID・プロジェクト・リージョンは環境変数で設定する。ローカルサーバーはgcloudのADCトークンを短期間キャッシュして使う。サービスアカウントのmetadata経路もアダプターにあるが、Cloud Run公開用の入口・ストア・拡張ログインは未完了。会社承認時に限りGemini Developer APIも設定できる。

UIは英語に統一し、言語切替は設けない。指示や回答はモデルが対応する任意の言語を使え、UI言語とは独立している。

## データとポリシー

- ブラウザ操作許可とAI送信許可を別々に持つ。AIは両方で承認されたHTTP(S)オリジンの情報だけを使う。
- AI送信許可は初期値空。利用者ごとの最大24時間の操作制限解除でも、AI送信許可は広げない。
- iframeの観察も両ポリシーの共通部分に制限する。
- 指示・URL・許可されたページテキスト・要素名・ツール結果・メモはサーバー経由でモデルへ送る。URLには必要に応じクエリも含む。
- ページの秘密入力欄は操作層でマスク。任意の個人情報や企業秘密を識別する分類器はない。
- ページ情報は非信頼データ。モデルによるポリシー変更・任意スクリプト・スクリーンショット送信を提供しない。
- 各モデル呼び出しと操作の前にポリシーを再取得。参照済みの全オリジンも再評価し、取り消されたページ情報を以後モデルへ送らない。
- ローカル履歴20件。実行ごとの取得テキストの保存上限は20万文字。

## 現段階の運用

1タスク・開始時に選択したタブで動く。新規タブ/許可外の現在ページからの開始では、そのページを読まず、明示的なnavigateで承認済みサイトへ移動できる。検索は行えるが、検知された業務書き込み・決済・権限付与・秘密情報入力では停止する。保護対象の検知は完全ではない。

既存の模擬プランは明示的なOffline demoだけで使う。AI未設定時の自動フォールバックはない。

## 残る範囲

- 会社のモデル・権限・ネットワークでの実証とChromeでの動作確認。
- Workspace/IAPによる拡張ログインと共有Cloud Run構成、共有ストア、監査、利用上限。
- 社内データ分類ルールの自動適用。
- 手動操作検知、複数タブ、継続会話、途中再開。
- PDF/Office/画像の専用パーサー。
- CRM特化版と会社DB保存API。
